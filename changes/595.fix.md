**An import that would change a requirement file that is not UTF-8 names it and lands nothing.** When an import joined decision rows into one of the product's own requirements, or marked one as replaced by a new text, and that file had been saved as Latin-1 or UTF-16, the import either raised a raw decoding error part-way through writing its plan, or said only that a requirement could not be marked replaced. It now stops before writing that file, commits nothing, and tells the person which file it is, the byte offset where it stops being UTF-8, and to save it as UTF-8.
