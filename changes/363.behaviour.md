**The worker image runs the worker and the panel in one container.** `beeverforge worker --with-panel` starts the durable worker and the panel against an engine run elsewhere, needing only `TEMPORAL_ADDRESS`, `TEMPORAL_NAMESPACE` and `TEMPORAL_API_KEY`, and is a valid `CMD` for the published `beeverforge-worker` image under its `tini`. SIGTERM stops both, and when either process ends the command exits with that process's status, so a restart policy sees it; `--panel-host 127.0.0.1` keeps the panel on the loopback for a container that publishes no port. `beeverforge up` now also exits with the status of the process that ended its set, where it exited 0 before. `docs/operations.md` shows the container command beside the compose stack's.
