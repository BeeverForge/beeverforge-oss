**An OpenFactory 0.7 deployment upgraded in place keeps its Temporal work, and stops running 0.7's schedules.** Until 1.0, the worker also polls 0.7's task queue `openfactory-jobs` with the same workflows and activities, so a job, a merge gate or a deploy watch that 0.7 started before the upgrade carries on; nothing new is started there. At boot, once BeeverForge's own schedules exist, it deletes 0.7's (`openfactory-poller`, `openfactory-preview-reaper` and each project's `openfactory-product-sweep-`, `openfactory-techlead-watch-`, `openfactory-card-questions-` and `openfactory-okf-refresh-` schedule), which would otherwise scan every board and report every sweep twice, and says in one log line which it deleted; one it cannot delete is logged as an error by name, and the next boot tries again. A poller paused in 0.7 is not carried over: `beeverforge-poller` starts running, so pause it again if the queue was held.
