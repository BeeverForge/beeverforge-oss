**A product's card template or rubric, the project registry or its seed that is not UTF-8 is named instead of raising.** A card template saved as Latin-1 or UTF-16 in the product's context repository raised a `UnicodeDecodeError` out of the card's drafting, a rubric or a registry seed saved that way was refused with the codec's own words, the project registry raised the same raw error, and UTF-16 without a byte-order mark was read as text full of NULs; each read also depended on the machine's locale. Each now takes the path it already takes for a file it cannot use — the template is refused and the next one (the product's `cards/template.md`, then the shipped layout) is used, the rubric is refused and the shipped one is used, the registry is refused as a file it cannot read, and the seed is not applied and the live registry is left as it was — in one sentence naming the file, the byte offset where it stops being UTF-8, and "save it as UTF-8". The shipped card layouts are read as UTF-8 whatever the locale.
