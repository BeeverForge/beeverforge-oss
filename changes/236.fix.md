**A forge token held in a rotating credential store is read again before it expires.** A token answered by the `file` store or an installed store was read once, when the job's runner was composed, so a job that outlived a one-hour installation token failed its final push with "Invalid username or token"; the forge and the tracker now ask the store again five minutes before the token's lifetime ends (`BEEVERFORGE_STORED_TOKEN_TTL`, an hour unset), hold it in between, and refuse by name if the store refuses it, while a token from the environment, a PAT and the GitHub App trio behave as before.
