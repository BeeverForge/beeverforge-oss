**A GitHub forge and tracker token held in a rotating credential store is read again during a job.** A token answered by the `file` store or an installed store was read once, when the job's runner was composed, so a job that outlived a one-hour installation token failed its final push with "Invalid username or token"; the GitHub forge and tracker now read it again every five minutes (every half lifetime under ten minutes), so a push carries the token the platform rotated in, and when the store refuses it or answers nothing once `BEEVERFORGE_STORED_TOKEN_TTL` (an hour unset) has passed since the last good read, the push refuses by name instead of using the expired token or the machine's own login. A token from the environment, a GitHub PAT, the GitHub App trio and other vendors' tokens behave as before.
