**An OpenFactory 0.7 deployment's `OPENFACTORY_*` variables are read as their `BEEVERFORGE_*` names, until 1.1.** Every process (the command line, the panel, the worker and the box) reads an `OPENFACTORY_<NAME>` as `BEEVERFORGE_<NAME>` when that name is unset, from the environment, `.env` and `~/.beeverforge/env`, and the `BEEVERFORGE_*` value wins when both are set. The old name is then removed from the process's environment, so a credential set under it reaches no box under either name. One warning line names the old variables read or ignored, never their values: rename them to `BEEVERFORGE_*`, because BeeverForge 1.1 removes the old names and reads none of them. Compose interpolates only the new names in `docker-compose.yml`, so a value the compose file sets itself, such as `BEEVERFORGE_REPOS_DIR`, wins over an `OPENFACTORY_*` in `.env.compose`.
