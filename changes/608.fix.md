**A Docker daemon slow to remove a box no longer crashes the job or loses its outcome.** When `docker rm -f` on a job's box did not finish within its bound, the job errored out with a traceback before any work if the box was a leftover from an interrupted attempt, and at the end of a run the same timeout replaced the run's outcome, so a hold or an open pull request surfaced as a failed job. The removal is now tried again once after a short wait; a leftover that still will not go parks the job with one sentence naming the box and the remedy, `docker rm -f <name>`, then resume, and any other step of starting the box that times out parks it the same way. A box left behind after a run is reported once, on the card and in the log, with the same command, and the run keeps the result it reached.
