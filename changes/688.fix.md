**A local-forge project whose repository belongs to a person works on the compose stack.** The worker and the panel run as root there, and git refused their calls in such a repository ("detected dubious ownership"), so the project could be neither proven nor run. When the process is root and another user owns the repository, the box's clone, the repository cache, the job's push and the local forge's own git now run as that owner inside it, in a short environment that holds none of the worker's credentials, and no `safe.directory` is written for it. A repository with two owners, one its owner cannot enter, or a worker image without `setpriv` is refused with the cause and the remedy, which `box prove` and the held job show. Other git calls the platform makes in such a repository are not changed.
