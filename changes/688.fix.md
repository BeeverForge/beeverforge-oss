**On the compose stack, the box's clone, the repository cache, the job's push and the local forge's own git run as the owner of a local-forge project's repository.** The worker and the panel run as root there, and git refused their calls in such a repository ("detected dubious ownership"), so the project could be neither proven nor run. When the process is root and another user owns the repository, those four now run as that owner inside it, in a short environment that holds none of the worker's credentials, and no `safe.directory` is written for it. A repository with two owners, one its owner cannot enter, or a worker image without `setpriv` is refused with the cause and the remedy: `box prove` shows both, and the held job shows the cause. Other git calls the platform makes in such a repository are not changed, git can still refuse them, and a whole job there has not been measured.
