**`beeverforge env context --ask` no longer asks in your own checkout.** The tech-lead harness was asked in the checkout the command was pointed at, which on a local deployment is the repository you commit from. On Kimi Code, which is read-only by instruction only, a question that disobeyed left its file in your working tree for you to commit. Each question is now asked in a temporary copy of the checkout, holding the files git tracks and the untracked ones it does not ignore, as they are in your working tree, and the copy is removed once the question is answered or fails. The copy holds no `.git`, so the harness cannot read the history, and it leaves out any link whose target is absolute or outside the checkout. A checkout whose files come to more than 256 MB is refused before anything is copied, naming the size; add what the question should not read to `.gitignore`, or run without `ask`. Copying this repository's own checkout (2,480 files, 34 MB) takes about a quarter of a second.
