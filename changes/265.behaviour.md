**A repository that keeps OpenFactory's `.openfactory/` folder is read where it is.** BeeverForge reads the platform's folder under both names: a repository with only `.openfactory/` has its manifest, its product's `product.yaml`, its profiles and its preview's files read from there, and what BeeverForge writes into it — `env apply`, `onboard`, `project init`, `product init`, `preview propose` and an import's record — lands there too, so nothing renames a client's folder on its own. A repository with neither folder gets `.beeverforge/`. When a repository has both, `.beeverforge/` is read, nothing under `.openfactory/` is, and `beeverforge doctor` says the `.openfactory/` folder is stale and to remove it once nothing in it is newer. The guards that keep writers and agents out of the folder hold for both names: the floor now protects `.openfactory/**` beside `.beeverforge/**`, and `certify` requires both.
