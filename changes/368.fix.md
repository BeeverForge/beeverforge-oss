**A changed-paths read git refuses is no longer read as a change that touched nothing.** When `git diff --name-only` fails in the box (exit 128, such as dubious ownership or a lock), a CI-repair pass now disarms auto-merge and holds for a person, and the knowledge gate says it could not run, each with git's exit code and words and asking you to make git usable on this workspace in the box, instead of treating the pull request as if no paths had changed. An empty diff git answered is still read as no paths changed.
