**The host's push no longer reads git configuration a job could write.** A job can write the git configuration of the repository it works in: the worktree box's `.git/config` and `config.worktree`, or the container box's host clone, which the box sees as /workspace. The authenticated push to the forge used to run in that repository, so a URL rewrite there (`url.<base>.insteadOf` or `pushInsteadOf`) could send the push, and its credential, somewhere other than the forge, and `core.sshCommand` could make the host run a program. Both boxes now push from a bare repository the host makes for each push, outside every mount: the job's commits are fetched into it, and the push runs there with the forge's URL as an argument. With no forge URL, the worktree box pushes to the `origin` the repository had before the job ran. The other host-side git calls that still run in a job's repository (the rebase onto a moved base, the local forge's merge) still read it; they are tracked in a follow-up issue.
