**An expired row is deleted from the `sqlite` metrics store, not only hidden.** Conversation messages kept for a period (ADR-0024), invitations and staged suggestions carry an expiry, and every read already hid them once it had passed, but nothing deleted them: on a deployment running the `sqlite` metrics store they stayed in the file for good. A schedule the worker creates at boot, `beeverforge-metrics-purge`, now deletes them every six hours. The delete zeroes what it frees and checkpoints the write-ahead log, so the text is in neither the store's file nor its `-wal` file afterwards, and each run logs `BEEVERFORGE_METRICS_PURGED kind=sqlite rows=<n>`. The first run after an upgrade deletes every row that expired before it.
