**On Azure DevOps, a ref qualified with the wrong project, such as `Owner/api` for an adapter of `api` in project `Desk`, is read where it is cloned again.** The forge cloned it from `Desk`, because the qualifier of the adapter's own repository is ignored, but it read the API for it (branches, pull requests, branch policies) in `Owner`, a project that does not exist. Both now pick the project with one rule, so the clone and the reads go to `Desk`, and a ref naming the own repository in another case, such as `Docs/API`, is read in `Desk` too. A ref naming another repository, such as `Docs/web`, still uses the project it names for both. The forge's list of disabled pipelines also matched a pipeline's repository by spelling, so a pipeline of `API` was not counted as `api`'s; it now matches without case.
