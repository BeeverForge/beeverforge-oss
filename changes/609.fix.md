**A merged job leaves its merge in the metrics.** When a job ends, its driver — the workflow and `beeverforge run`/`poll` alike — now writes one `job` row with the final state, the pull request and the platform stamp, marked `extra.ending: true` and written once, so a pull request merged by hand shows as a job that ended merged. And when the forge closed the issue before the workflow saw the merge, the card's door still records `merged` for that pull request, once, without rewriting the card. The metrics docs (`docs/reference/metrics.md`) say what an ending row is and that `card_transition` rows without `event` are effect outcomes.
