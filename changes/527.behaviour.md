**A registered project's repository, tracker or CI can be changed in one action.** The `project_update` action, with `beeverforge project update <name>`, writes a new `repo_path` (with the axes its host says), a different board, tracker kind or credential variable, or a different CI kind, and keeps the project's model, language, preview policy, `enabled` and attached board. It makes every refusal `project_add` makes for the same input — a foreign host, missing coordinates, an invalid `token_env`, a second GitHub organisation, a shared slug — and writes nothing then; a call with nothing to change, or a field the action does not take, is refused naming it, an unregistered name is refused naming the roster, and a call that matches what is held answers `changed: false` without rewriting the registry. The answer and the audit record name the fields changed, never a value. `project_add`'s refusal of a project registered differently now points at it.
