**A git call from the repository cache or the worktree box no longer waits for a username or password at a terminal.** Both ran git with the credential prompt on, so a fetch, clone or `ls-remote` that carried no credential, or a rejected one, asked `Username for ...`: an attended command such as `box prove` sat on that prompt and the worker waited until its timeout. Every git call they make now runs with `GIT_TERMINAL_PROMPT=0` and `GCM_INTERACTIVE=never`, which neither a caller's environment nor the process's can turn back on, so a call that cannot authenticate fails at once with git's own error. The box still passes the environment a caller gives it as the whole environment, and leaves a command that is not git as it was.
