**`beeverforge migrate <project>` proposes renaming the former `.openfactory/` folder to `.beeverforge/`, one pull request per repository.** It looks at the project's code repository, the repositories named with `--source` and its context repository, each from a throwaway clone of its base branch. A repository that carries only `.openfactory/` gets one pull request on `beeverforge/migrate-folder` that moves the folder with `git mv` and rewrites the `.openfactory/` paths written in the moved files, such as a `preview.compose` value; nothing outside the folder changes, and the pull request names the files whose paths were rewritten. A repository already on `.beeverforge/`, or with neither folder, is left alone, and one that carries both is named, with no pull request, for a person to reconcile. It is safe to run again: a pull request still open is named rather than opened twice, and after the merge the run finds nothing to do. A repository whose clone, push or forge refuses is one line with its cause and remedy, and the others still run. Nothing is written into a checkout: a project whose forge is this machine is refused, with the `git mv` to run there. `--yes` is required, as for `onboard`.
