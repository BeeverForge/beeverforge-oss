**A `product.yaml` or a compose file that is not UTF-8 is refused by name instead of crashing.** A `.beeverforge/product.yaml` (or `.openfactory/product.yaml`) saved as Latin-1 or UTF-16 raised a decoding error out of the product module, the preview, `beeverforge product init` and the proposal of a product's preview, though it looked right in the editor that saved it. Each of them now answers with one sentence naming the file, the byte offset where it stops being UTF-8 text and the remedy, save it as UTF-8, and the compose files a preview reads, with the files their `extends:` names, are refused the same way. UTF-16 without a byte-order mark is caught too: its first NUL byte is named as not UTF-8 text, where before it failed as YAML in words that named neither the encoding nor the remedy.
