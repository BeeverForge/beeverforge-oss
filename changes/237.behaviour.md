**`onboard` is now a catalogue action, reachable through both transports with the catalogue's authorization and audit.** Through the API it starts the onboarding on the worker and answers the run's handle, and each repository's steps (read, manifest, proof, map, pull request) are journaled as they end. An unknown project, or a source that is not a repository the project's forge can name, answers a reason rather than an error. A second run finds what the first left and says that nothing changed. The CLI verb maps over the action with the same output and exit codes.
