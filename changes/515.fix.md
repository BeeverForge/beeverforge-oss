**The pull request the factory opens on Azure Repos is attached to its card's work item.** It named the card `#1234` in the title and body, which Azure DevOps reads as plain text: the commit was linked to the work item and the pull request was not, so a person added the link by hand on every card. The pull request is now created with the work item as a reference where the forge owns the card (an Azure board over Azure Repos in the same organisation; the work item may be in a different project than the repository). If Azure DevOps refuses the create because of the reference, the pull request opens without it and the log says `BEEVERFORGE_PR_LINK_REFUSED`. Nothing is closed or moved: the card's state stays its tracker row's. A pull request that was already open is not attached afterwards.
