**The reviewer's summary and findings no longer link an issue or notify anyone from the pull request.** A `#12`, `owner/repo#12`, `GH-12` or `@someone`, or an entity spelling one (`&#x40;someone`), in the review's summary or a finding was written into the pull request body, and into the review posted on it, as the reviewer wrote it, so it linked an unrelated issue or mentioned a stranger; `#12` and `GH-12` are now written `card 12`, and a name, or a `GH-12` that rewrite misses (inside `_` emphasis, or after a letter that is not ASCII), carries an invisible zero-width space that keeps it readable and links nothing, and an `&` is written as text, so no entity is decoded into one; inside closed code, a fence or an address GitHub turns into a link, where an entity is not decoded, an `&` is left as written, so `a && b` and `?a=1&b=2` read and link as they did. An address GitHub does not link (`https://&#x40;someone`, one glued to a word) has its `&` written as text too, and so does an autolink in angle brackets whose scheme is not `http` or `https` (`<ftp://…>`, also one glued to an address before it, with or without a backslash before its `<`), which is written so it is no autolink (the `:` after its scheme escaped), since inside an autolink a backslash escapes nothing.
