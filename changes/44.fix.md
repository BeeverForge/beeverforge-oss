**A stopped job now ends its agent and publishes nothing after the stop**: `stop` used to end only the job's workflow, and the agent pass went on in its worker thread, so a stopped job could still push, open a pull request, merge it and write on its card. Now, before each step that would push, open or review a pull request, request reviewers, merge, move the card or comment on the ticket, the job asks the engine whether its workflow is still running, and takes none of those steps once it is not (if the engine cannot be reached at that moment, the step goes ahead). At the job's next heartbeat, up to about a minute later, the worker also kills the agent and the processes it started, then removes the job's worktree. On the worktree box this includes background processes and, on Linux, processes that left the agent's process group: they are found by a per-job marker in their environment, so a process that clears its own environment escapes. The box's commands also get a per-job temporary directory (`TMPDIR`), which is removed along with the worktree. A harness that sets its own temporary directory for the commands it runs still writes there (Claude Code does, under `/tmp/claude-session-tmp/<id>`), and whatever a killed command left there is not removed. On the container box, removing the container ends everything inside it. A forge call already in progress when the stop arrives is not undone: a pull request being opened or a merge being made at that moment still goes through. When that happens, the job comments on the ticket and notes in its journal what landed (the pull request was opened, its auto-merge was armed, or it was merged into the base branch) and what to do about it (close the pull request, turn auto-merge off, or move the card to Done by hand so it is not picked up again), and then stops. The card stays where the stop put it. `stop` now says what its worker was told: whether the worker was heard from recently, or has gone silent so that nobody knows whether its agent is still running.
