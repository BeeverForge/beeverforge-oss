**`beeverforge doctor` waits as long as the engine's deadline before it calls the engine, its UI or the panel not listening.** It gave up after a fixed 1.5 s, so on a loaded machine a listener that answered late was reported as down while every other read of the same engine waited `BEEVERFORGE_ENGINE_DEADLINE` (3 s unless set). The check now waits that deadline, and a listener that did not answer says how long the doctor waited and that `BEEVERFORGE_ENGINE_DEADLINE` raises it.
