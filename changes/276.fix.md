**A rebase before merge runs as the factory's bot, and only a real conflict is reported as one.** The worktree box now rebases with the job's bot identity, so a host with no git identity no longer refuses the rebase, and a rebase that fails with no unmerged path (a held `index.lock`, a full disk) parks the job as "could not rebase" with git's own sentence, redacted, instead of as a conflict that was never there.
