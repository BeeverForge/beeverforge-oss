**An existing metrics store keeps its mode, so restrict it by hand.** Only a new store is created `0600`; a `metrics.db` created by an earlier version stays `0644`, and so do its `metrics.db-wal` and `metrics.db-shm` and the copies `forget` took before this release under `backups/forget-*/metrics.db` (the copies it takes from now on are `0600`). In the state volume (for compose, `beeverforge_state`, mounted at `/var/lib/beeverforge`), run `docker compose exec worker sh -c 'chmod 600 /var/lib/beeverforge/metrics.db*; chmod 600 /var/lib/beeverforge/backups/forget-*/metrics.db'`; a "No such file" for `backups` only means there are no earlier copies.

The panel and the worker must run as one user, since both open the same store: compose runs both as root, and a deployment that gives them different users locks the panel out of the store.

A symbolic link at the metrics store's path (`BEEVERFORGE_METRICS_DB`) is now refused rather than followed: if yours is one, point `BEEVERFORGE_METRICS_DB` at the file it names.
