**A long pull-request text in any script reaches GitHub, and one GitHub would not take is refused by name before it is sent.** Opening a pull request, bringing an open one up to date, reviewing one and rewriting its description passed the whole text to `gh` as one command-line argument, which Linux refuses over 131,072 bytes: a text GitHub accepts (up to 65,536 characters) failed from about 43,690 characters in a 3-byte script such as Chinese or Japanese, as a raw `OSError` or a description left on an earlier attempt. The text now goes to `gh` on its standard input, and an argument the kernel still refuses is a named failed call that says to send the text on stdin. Before the call, a text over GitHub's 65,536 characters, a title over its 256 characters and a title holding a NUL character are now refused with a sentence naming the cause and the remedy, never cut; a NUL in a title used to end the create in a traceback. Bytes that were not valid UTF-8 in a title or a text are replaced with U+FFFD, so the pull request is still opened with only those bytes marked, where they used to end the write in a `UnicodeEncodeError`. A NUL or another control character in the text itself is sent as written.
