**A box daemon that runs as another uid than the core can enter the job's workspace.** The container box made each workspace in `BEEVERFORGE_WORK_DIR` with mode 0700, so the access a deployment gave that uid on the work dir through a default ACL never reached it: a new directory's ACL mask is its group bits, and the box refused to start with `chdir to cwd ("/workspace") ... permission denied` (`docker run` exit 126). A workspace in the work dir is now 0770, whatever the umask; "other" stays out, and a workspace in the system temp directory, with no work dir set, stays 0700. This covers a work dir shared through a default ACL. A work dir shared through a setgid group keeps its setgid bit on the workspace, but also needs the core to run with umask 0002 or 0007, or the clone's subdirectories are not group-writable and the box cannot commit.
