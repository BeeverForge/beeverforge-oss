**A project's board columns can be read and set without editing the registry.** The `project_board_columns` action answers the project's board: its kind and address, the columns the board reports, the column each stage the core defines is (a stage no column is shows as unmapped, as the doctor's `board_columns` reports it) and the column that dispatches work. The `project_set_board_columns` action, with `beeverforge project set-board-columns <name> todo=<column> …` and `--pickup`, writes that mapping to the tracker option the board reads (`columns`, `status_map` on Jira) and `pickup_status`. It merges into what is held, answers the new mapping, and changes nothing when the mapping is already so. It refuses, saying `Nothing was changed` and naming the board's columns, a column the board does not have, a stage the core does not define, two stages on one column, and a pickup that is not the `todo` column. Both belong to the installation's administrator, like the other `project_set_*` actions, the set leaves one audit record whether it was allowed or refused, and the panel shows the mapping with the project's other settings. The doctor's `board_columns` and `board_stages` and the poller read the change on their next pass, with no restart.
